# Архитектура приложения Country Search

## 1. Отмена устаревших запросов (Race Condition)

В приложении реализована реальная отмена сетевых запросов с помощью `AbortController`.

**Почему не флаг «актуальный ли это ответ»:**
Использование флага (например, `isActualRequest`) или сравнение таймстампов не решает главную проблему — сеть продолжает работать, и устаревший ответ всё равно приходит на клиент, нагружая канал и память. Более того, флаг не спасает от ситуации, когда устаревший ответ приходит _между_ моментом ввода нового символа и срабатыванием `debounce`.

Мы используем `AbortController.abort()` **при каждом изменении ввода** (до срабатывания debounce). Это гарантирует, что:

1. Сетевой запрос физически прерывается (в Network tab он помечается как `canceled`).
2. В `catch` мы можем отличить нашу собственную отмену (`AbortError`) от реальной ошибки и не показывать её пользователю.

## 2. Выбор задержки debounce

В `SearchController` используется задержка **300 мс**.

- **Если её убрать (0 мс):** приложение будет отправлять запрос на каждое нажатие клавиши. При быстром наборе это создаст огромную нагрузку на API и может привести к блокировке со стороны сервера (Rate Limit).
- **Если сильно увеличить (например, 1000 мс):** поиск будет казаться «заторможенным», пользователь не увидит мгновенной реакции.
- **300 мс** — это золотая середина: достаточно, чтобы пользователь успел допечатать слово, и при этом интерфейс кажется отзывчивым.

## 3. Сложность (Big O)

- **`mapCountryResponse`**: `O(n * m)`, где `n` — количество стран в ответе, а `m` — среднее количество языков у страны. В худшем случае это `O(n)`, так как количество языков — константа (обычно не более 5-10). Функция проходит по массиву один раз и создает новый массив (чистая функция).
- **`debounce`**: `O(1)` по памяти и времени, так как хранится всего один идентификатор таймера.

## 4. Принципы чистого кода

При написании приложения были применены следующие принципы:

- **Single Responsibility Principle (SRP)**:
  - `api.ts` — только сетевые запросы и маппинг.
  - `debounce.ts` — только задержка вызовов.
  - `search-controller.ts` — управление состоянием поиска и отменой.
  - `ui.ts` — только работа с DOM.
- **Open/Closed Principle (OCP)**: `SearchController` принимает коллбэки `onSuccess` и `onError`, что позволяет менять поведение UI без изменения самого контроллера.
- **DRY (Don't Repeat Yourself)**: Логика классификации ошибок вынесена в единую чистую функцию `classifyError`.
- **Отсутствие `innerHTML`**: Весь UI собирается через `document.createElement`, что исключает XSS-уязвимости.
- **Pure Functions**: `mapCountryResponse` и `classifyError` не имеют побочных эффектов и легко тестируются.
